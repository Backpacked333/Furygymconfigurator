## Image truth and lifecycle

The initial large image is one fixed local historical aesthetic reference:

- Source revision `97f204ffff`, source design `4f807d1dd16ad6aa`, fixed `front-left` view.
- File `/stills/97f204ffff/4f807d1dd16ad6aa/front-left-wide-1600.7ea9c6eb.webp` from the unchanged historical manifest.
- Its persistent, conspicuous label is **Historical reference — not this configuration**. The reference never changes with family, size, finish, look or camera controls. It is not a current approved artifact or art-direction parity claim. A missing file gets an honest unavailable state.

`View mock preview` exposes the actual service diagnostic. It always says **Mock preview — not a current design image**, includes the generator/source request revision and distinguishes selected versus previous requests. A matching digest never becomes an exact/current approved photograph. No invented photorealistic output is generated.

`imageClient.ts`:

1. Captures one immutable full v4 revision; collapses rapid clicks with a 120 ms admission delay.
2. POSTs the strict config-only request to `/__fury-prototype/v1/images` with same-origin credentials and no-store behavior.
3. Validates submission status, all identity fields, catalog and deterministic diagnostic artifact bytes through the frozen async protocol parsers.
4. Polls only the server-issued interest path, honoring retry guidance with a minimum 250 ms interval, at most 20 polls and a 25-second overall deadline. There are no automatic retries.
5. Decodes the complete image and verifies intrinsic dimensions before publishing it. The hook closes the old request before the next committed revision can paint; an old validation/decode completion cannot replace a newer selection.
6. Aborts local work and attempts a real, bounded three-second interest-only detach on replacement/unmount. A late submission can still be detached but cannot update the UI. Detach failures are not claims that shared/provider work stopped.
7. Rejects oversized response bodies above 32 KiB, malformed/future/identity-mismatched responses, corrupt artifacts and decode failures. Terminal failed/expired/cancelled outcomes retain the design and any explicitly previous diagnostic. Retry is explicit and disabled for non-retryable failures. Capacity exhaustion always disables immediate Retry, including older server replies incorrectly marking it retryable; it explains retained-request/lifetime-budget limits without claiming recovery or changing those limits.

The current/previous/pending/error/unavailable states never trigger Three, workers, textures, cloud or PDF. 360°, approved-image downloads and strict image/PDF export remain visibly disabled with explanations. The only image download is the selected validated mock SVG, with its embedded disclaimer and full request digest in the filename; it is disabled during pending/error/previous states. No canvas screenshot or lower-tier export substitution exists.

## Persistence and share boundaries

- Full-v4 local save/load, local share, JSON export and 50-step snapshot Undo/Redo operate independently of imagery.
- Sole save namespace: `fury-prototype-v4-draft-1`, via the domain storage API. No mount/hash autosave, implicit saved-design restore, automatic hash import, v3/review overwrite or migration.
- Saved designs and incoming shares open explicitly, as one history step. Unknown or malformed incoming data is not interpreted as the current design.
- Explicit save captures a frozen snapshot. Replacement requires exact observed-raw comparison, verified archive-before-write and verified readback. Malformed/future originals additionally require the explicit **Preserve original and replace with this design** action. Failures/conflicts do not claim success; re-inspection is explicit.
- Web Locks serialize cooperating saves where supported. The synchronous fallback retains compare/recheck safeguards but is not a cross-tab transaction against noncooperating writers. There is no automatic recovery-copy cleanup.
- Share prefix: `#fury-v4=` plus the percent-encoded serialized envelope. Links retain only `?prototype=images`, not old cloud/bake query flags. Explicit link creation uses history push rather than destructive hash replacement; an invalid current fragment is not replaced at all. Back/hash navigation exposes a snapshot to open explicitly, not an implicit rewrite of the current design.
- Exact original raw fragments and malformed saved values can be downloaded as text. Copy denial exposes a read-only snapshot link and JSON fallback. A skip-link prevents default hash navigation and focuses the configuration panel without modifying any share fragment.
- Optional recovery inspects raw legacy draft/library and standalone-review records only on demand. Downloads preserve their inspected text; legacy preservation uses the existing verified archive helper without conversion. Prototype recovery copies are also inspectable/downloadable. Unrelated localStorage keys are not displayed.
- No general JSON upload/import UI or production conversion is supplied. No customer design is silently imported or migrated.
