# P03 asset integrity and rights evidence

## What has actually been checked

The private preparation inventory pins 79 local files: 78 WebPs from 27 texture groups and `public/textures/sources.json`. Preparation compares expected and observed byte hashes/sizes, rejects missing or changed consumed resources, rejects symlinks/traversal and cross-checks the entire private build texture closure. Source/build/dependency receipts bind the authored geometry, materials and actual code that reconstructs them.

**This is not a legal clearance.** The repository credits 24 upstream texture groups and locally generates three microtexture groups. No acquisition receipt linking the exact processed bytes to a verified license, ownership authorization or approved usage scope was found in this implementation audit. Therefore all 27 groups remain held, even if an upstream library is described as public/CC0. Preparation does not fetch provenance URLs or infer rights from a matching hash.

The authoritative per-group IDs and credited origins are in `src/render/prototype/assetInventory.json`; those URLs are evidence labels only, not render inputs. `validatePreparationAssets()` returns 28 asset-rights holds (27 texture groups plus product/brand), a font conversion hold and an execution-authorization hold. The strict reference manifest adds conversion, art settings and worker dependencies to its holds.

An approval workflow must record evidence and reviewer identity and issue a reviewed inventory/contract revision. Do not edit `rights: held` to `evidenced`, regenerate hashes to conceal changed assets, or treat execution flags as informal operator toggles. The P03 command has no rights-approval or execution switch.
