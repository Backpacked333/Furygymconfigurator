It applies the two documented stress selections and uses the existing gallery camera authority. `createG1CompositionIdentityAudit()` returns all 28 logical design/presentation/request identities plus derived cameras. It does not invent source, geometry, material, runtime or image hashes and does not produce the CPU plan's source-bound `compositionDigest`.

`validation-fixtures.test.ts` compares these selections against both the frozen six samples and the **existing** CPU fixture/plan enumerator. For the enumerator unit test only, its preparation dependency is replaced by explicitly synthetic metadata; actual geometry/material preparation is not executed and no synthetic receipt is written. Thus the test verifies enumeration, strict designs, camera calculations, logical identities and blocked accounting—not CPU provenance, asset bytes or browser execution. It checks the real capture contract's near/far 0.1/2000, not clipping metadata from the synthetic preparation seam. ## Verified contract limitations to resolve at integration

The final describe block in `validation-contract.test.ts` deliberately characterizes these limits with **synthetic in-memory data only**. Passing those tests records a gap; it does not authorize publishing their inputs. If the integrator hardens the shared contract after parallel lanes finish, change the characterizations into rejection tests.

1. **No applied-scene identity in the frozen browser result.** `validateWorkerResult` compares echoed job/capture IDs and expected camera values. Its shape has no independently measured applied full config, resolved inventory/placement, geometry/material/light state or applied-profile receipt. A synthetic result with expected IDs/camera/effect claims and non-PNG base64 passes this helper. `validateCaptureReceipt` can likewise validate runner-assembled claims without seeing the scene. This is a substantive gap if these helpers alone are described as proof that pixels depict the requested design. The integrator must implement and bind the independent evidence chain below, or explicitly report this identity proof as missing; do not self-certify it from the request echo.
2. **Effect applicability and readiness are declarations, not measured proof.** Required architecture/equipment/textures/environment/fixture/probe/MSAA omissions fail receipt validation, and the five Lite omissions cannot be relabelled enabled. But the night/mirror/glass fixture can still submit `not-applicable` for mirror/glass/canvas/site-field states and pass. Review actual graph applicability and readiness; accepting a false `not-applicable` is not honest missing-effect reporting. Hardware/software classification also needs actual adapter evidence, not a supplied enum alone.
3. **`validateDecodedArtifact` is deliberately post-decoder, not a decoder.** A 44-byte header-only non-image with separately supplied ramp pixels passes it. It checks PNG signature/header/dimensions and statistics, not CRC/chunks/deflate or that those pixels came from those bytes. The runner must independently decode the exact returned bytes, with strict CRC/order/filter/inflate bounds, before this helper. A colourful ramp also passes the pixel statistics: they detect gross corruption, not architecture, semantic identity or visual quality.
4. **Completion shape is not completion proof.** `validateCaptureTerminal` checks job/capture binding and width/height, but can accept inconsistent `rgbaBytes` in its nested marker. It does not read files, verify the receipt hash or ensure exclusive last-only publication. Runner must derive marker metadata from the independently validated/read-back artifact and receipt, compare all fields and publish last. The integrator should consider strengthening nested pixel consistency rather than relying solely on call order.
5. **Attempt policy is not persistence.** The pure attempt helper accepts an empty history every invocation. It cannot prove global append-only history, no other process or a stopped child. The runner/integrator retains one history across directories/processes, records admissions before launch and preserves failed/timed-out/cancelled/uncertain work. Do not reset it to obtain more permission.

These are verified boundaries, not a claim that the parallel runner/scene implementations exploit them or already satisfy their obligations. This lane does not import or assert existence of future runner/browser files.

## Required independent configuration-to-byte evidence chain

The integration captain must review actual evidence, not only matching requested IDs or a worker saying “enabled.” An independently collected browser receipt must describe **applied scene state**. Reading `job.request` twice and computing the same digest is not independent observation.

1. **Trusted inputs first.** Independently parse/freeze the requested full v4 design and recompute its domain identities. Retain exact trusted source, asset, lockfile and emitted closure manifests with names/lengths/SHA-256; hash actual bytes, not catalog labels. Verify the closure excludes forbidden paths. Freeze a byte snapshot or revalidate it before publication. Give the private page separately trusted bootstrap build metadata, not the caller's claims; compare it at ready and render. Avoid a self-referential bundle digest.
2. **Capture applied full state from the mounted private graph.** After strict config-only assembly, collect the config actually passed to trusted builders and independently traverse the resulting scene. Bind family/size/structure/appearance, arrangement identity and the authoritative item IDs/SKUs/placement matrices, geometry/material counts and applicable source/buffer/material/texture fingerprints. Confirm door pose and visible additions, not just the product label. Bind the applied environment/look, fixture state, exposure/tone/output color state and probe/light resources. Explicit feet/+Y/+Z/+X and transform conventions must agree. A config digest with missing inventory or the wrong door geometry is a failure.
3. **Observe camera and profile, do not manufacture them from the job.** Read the mounted camera position/up/world/projection matrices and actual lens/clipping/aspect; compare target direction/framing to independently derived gallery values. Read actual canvas/render-target/encoded dimensions, DPR, renderer pipeline/MSAA, tone mapping/color space and frame count. Derive the receipt at the final captured frame, not before a later async scene update. No free controls, inherited v3/app state or hidden quality reduction. Tolerances for numeric observations must be explicit and bounded rather than accepting an arbitrary pose.
4. **Prove readiness and runtime.** Record measured API/backend, adapter/browser version and software/hardware/unknown provenance. Observe required successful texture decode/upload and failed-resource status; a progress counter that counts failures as settled is insufficient. Observe probe captures and the site-light worker's matching completion, not just dispatched tickets. After all required changes, enforce 500 ms quiet, at least two post-readiness frames and the fixed 8–64-frame envelope. If an asynchronous effect cannot be observed, mark it approximate/omitted with the actual reason; fail if required. Never invent success to avoid a timeout.
5. **Link observations to these bytes.** Return bounded applied-state evidence from the owned isolated page for this one job and bind it to the exact output byte digest; collect it at capture completion. Node independently decodes and hashes exactly the returned PNG, verifies format/dimensions/opaque nonuniform pixels, compares browser/runner identities and full applied-state observations against the independently resolved expected state, and rejects mismatches. Keep the raw independently obtained page result/evidence and resource/network/driver provenance within explicit metadata limits so review can distinguish observed fields from expected fields. No generic caller-script evaluate endpoint or unsolicited fields. A contract extension for applied-state evidence must be reviewed by the integration owner; do not quietly add unchecked fields to strict envelopes.
6. **Recheck and publish exclusively.** After cancellation/deadline checks, write image and receipt exclusively in a new owned external-output directory; reread them, independently decode/hash the reread image and recompute receipt bytes/hash. Compare the final completion metadata exactly to these verified records. Only then publish the exclusive `COMPLETE.json` marker last. Any failure keeps prior outputs intact and produces no complete marker. Preserve partial new outputs for diagnosis according to ownership policy; never substitute a previous still, synthetic PNG or stale frame.
7. **Independently inspect delivered pixels.** The receipt chain detects inconsistent assembly and stale output; it is not a mathematical proof of pixel semantics. Inspect all actual local PNGs at native dimensions against their frozen configuration, including inventory, geometry, door/opening, mirror/glass and composition. Gross pixel statistics cannot establish subject identity. Document unresolved visual defects and missing effects. A draft local image may be useful evidence without being visually qualified; no G1 score or product approval follows automatically.

The current `WorkerResult` lacks the applied-state fields described above. The integrator must make an explicit reviewed contract/evidence decision after the lanes finish, not claim this lane implemented a new runtime protocol. Logical/capture identity remains distinct from the encoded byte digest; same requested state may yield different encoder/backend bytes. Neither identity is a rights approval, cross-device equality guarantee or production cache authorization.

## Mandatory negative-path and containment checklist

These are **integration review requirements**, not claimed runtime tests from this lane. Every exercised path needs a bounded failure receipt, child/output state evidence and preservation verification. Structural tests here cover schemas/identity/accounting only.

- [ ] Invalid/future/legacy design; unknown keys at every level; injected mesh/equipment/transform/URL/script/shader; incompatible families/openings/additions; duplicate additions; wrong profile/aspect/approval flags. Reject before scene assembly/admission; no normalization into an easier permitted job.
- [ ] Each sample ID swapped with every other request; stale job/result/progress/receipt; wrong source/asset/bundle/lockfile/revision; mutated camera/profile/door/look/finish; late completion after cancellation. Independently recomputed valid digests still cannot admit an unpinned composition.
- [ ] Missing/corrupt/changed/oversized local texture or module; failed texture load counted as settled; never-resolving texture/probe/site-worker; lost graphics context and unsupported backend. No placeholder materials, lower quality, old image or unbounded fallback.
- [ ] External HTTP(S), WebSocket, file/cloud/metadata/private-network URLs, redirects, encoded traversal, double encoding, unexpected query/Host/method, symlink escape, unknown fallback resource and excessive request/byte counts. Deny at exact static server allowlist and owned browser/worker target interception, including nested workers; record denial as job failure. No proxy/upstream fetch. Provenance URLs remain text only.
- [ ] Startup failure, browser crash, blocked JS/GPU, stalled encode/decode/CDP, resource/metadata inflation, malformed base64, truncated PNG, bad CRC/chunk order/filter, interlacing/unsupported format, missing/duplicate IHDR/IEND, huge dimensions, inflate bomb, appended junk, transparent/uniform/near-empty pixels and mismatched readback bytes. The independent decoder must actually reject invalid images.
- [ ] Hard startup/job/run deadlines (30 s / 180 s including startup through publication / 1,530 s), external watchdog, max 5 s cleanup, one owned child at a time, cancellation at each await/publication boundary. Terminate only the owned child process group; verify exit. A page promise resolving is not proof of stopped browser children.
- [ ] Six unique successes, two diagnostic retries and eight total attempts enforced through retained history across invocations. Reject successful repeats, concurrent jobs, orphan/duplicate retries, reset history and stale publishers. Bounded diagnostics are not permission to increase resolution/frames/deadline or start a ninth attempt.
- [ ] Existing, malformed, incomplete or symlinked output destination; directory replacement; two writers; disk-full/permission/readback/hash failure; cancellation or process death during image/receipt/marker publication. Preserve old data byte-for-byte; no overwrite, false completion or reuse of prior immutable CPU receipts.
- [ ] Launch the absolute installed headless executable with a disposable owned profile and fresh endpoint, never the desktop Chrome shim/current profile/CDP. No browser/engine download or dependency install into shared `node_modules`. Pass no secrets to pages/receipts/logs or unnecessarily inherited child environment. No testing agent, visible desktop browser or app recording in this batch.

## Missing effects must remain visible

Every actual capture receipt must report each of the 18 contract effects once, with state and a specific truthful detail. Required architecture, fixed equipment, material textures, environment, fixture lighting, interior probe, site probe and MSAA must be observed enabled or the capture fails. Console/signature canvas, thin glass and site-light-field applicability/readiness must be checked against the actual scene. Do not use `not-applicable` to hide a missing feature that is present in the requested configuration.

The fixed Lite route **omits AO, screen-space GI, screen-space reflections, bloom and path tracing**. Lite mirror is approximate probe-lit metal, **not planar or ray-traced reflection**. Any further software-backend, glass, texture, canvas, probe, environment, light-field or finishing compromise must appear in that image's receipt and review notes. Existing CPU receipts explicitly omit more features and remain partial preparation evidence; they cannot be promoted to browser material fidelity. Reusing architecture and producing nonempty pixels is not visual parity.

VM software graphics must be labelled as software with measured adapter evidence. Unknown acceleration is not hardware. Fixed frame/deadline limits are containment bounds, not measured performance. No laptop, GPU-hardware, UI latency, customer-delivery or physical-device claim follows from structural tests or a SwiftShader capture.
