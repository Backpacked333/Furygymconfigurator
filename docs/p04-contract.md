# P04 local safe-image control contract

Authority: `src/image-service/control-plane/contracts.ts`. This is a separate, unmounted, local diagnostic control plane, not a replacement for the retained prototype/real-image lanes or the default v3/B UI. Existing domain/catalog/presentation authority remains unchanged. All costs are **integer synthetic microcurrency**, never provider prices or spending permission. `EXECUTION_POLICY` is frozen; paid execution, production claims and public streams are permanently false in this phase. No provider credentials, rendering, graphics capture, network provider calls, approval exceptions or product catalog are introduced.

## Frozen ownership and implementation names

- Contracts: `contracts.ts`, `contracts.test.ts`, this document.
- Ledger agent: `ledger.ts`, `ledger.test.ts`; export `SqliteLedger implements Ledger`.
- Object agent: `objects.ts`, `objects.test.ts`; export `FileObjectStore implements ObjectStore`.
- Worker agent: `provider.ts`, `worker.ts`, `watchdog.ts`, corresponding tests, `scripts/p04-watchdog.ts`; export `LocalFakeProvider implements FakeProvider`, `ControlWorker implements Worker`, `IndependentWatchdog implements Watchdog`.
- API agent: `service.ts`, `auth.ts`, `api.ts`, corresponding tests; export `SafeImageService implements ControlService`, `createControlMiddleware(options: ControlHttpOptions): ControlMiddleware`. Auth adapter constructor/factory details may remain implementation-local, but its output must implement `Authenticate` without hardcoded user rights.
- Integrator: integration tests, `scripts/p04-verify.ts`, `docs/p04-safe-image-service.md`, README. Interface repairs only after parallel agents stop; otherwise report a mismatch rather than silently change this contract.

Each implementation class takes the corresponding `*Options` object exported from contracts. Additional **test-only** injection options may be defined in the owning file; production inputs cannot select fake outcomes, execution commands or keys. Do not create empty success-returning classes to satisfy these names.

## External protocol and authentication

Base: `/__fury-control/v1`; protocol literal: `fury.safe-images.local@1`.

| Method and route              | Body/result                                                                      |
| ----------------------------- | -------------------------------------------------------------------------------- |
| `POST /images`                | Strict `{ protocol, design: DesignEnvelope, idempotencyKey }`                    |
| `POST /exports`               | Separate strict `{ protocol, design, idempotencyKey, format: 'diagnostic-svg' }` |
| `GET /interests/:id`          | No body. Auth-owned status only.                                                 |
| `POST /interests/:id/cancel`  | Strict `{ protocol }`; interest-only detach.                                     |
| `GET /interests/:id/artifact` | Authenticated bounded byte delivery, no arbitrary object-key route.              |

`design` MUST be the existing strict v4 envelope, including its named presentation and `outputProfile` (`web-hero` or `web-thumbnail`). There is no duplicate top-level profile override. `imageRequestSchema` and `exportRequestSchema` reject every unknown field. Asset URLs, meshes, arbitrary cameras, samples, scripts, callbacks, worker commands, priorities, principal/experiment identifiers, paid flags, caller digests and private worker fields are not accepted. `format` is rejected on the image route. Neither export format nor profile claims PDF, photorealism, exact approved imagery or a strict export.

Idempotency keys and opaque IDs are ASCII `[A-Za-z0-9_-]{16,128}`. Keys are mandatory. Internal generated IDs should use at least 192 random bits; the syntax minimum is not a server randomness recommendation. Maximum uncompressed UTF-8 JSON body is 16 KiB, checked before parsing. HTTP applies bounded request concurrency, body timeouts, strict media/encoding handling, no request-body identity, no proxy trust by default and same-origin/direct-loopback protection for the local adapter. There is no public worker/kill/policy/stream endpoint.

`AuthContext = { principalId, experimentId, scopes }`, where scopes are unique members of `images:read`, `images:write`, `exports:write`. Auth is supplied **out of body** by `Authenticate(request: IncomingMessage): AuthContext | null | Promise<AuthContext | null>`. Schema validation is not authentication. A trusted injected credential verifier must resolve identities/scopes; missing/invalid auth returns 401, missing scope 403, another principal's interest 404. No automatically minted budget principal and no wildcard production rights. Service methods still check required scopes; all ownership includes both principal and experiment.

- Exact verified active cache result: 200 and ready. “Exact” means this immutable **diagnostic** revision, not approved current-design imagery.
- New/coalesced pending work: 202 with job/interest state and polling delay.
- Valid JSON but invalid schema/domain: 422. Malformed JSON: 400; oversized body: 413; unsupported media/encoding: 415; method: 405.
- Idempotency rebinding: 409; ended idempotent interest: 410, not resurrected.
- Budget/capacity cap: truthful 429; killed, unavailable store, unresolved execution or publication/verification failure: 503. No unverified cache fallback or fabricated ready.
- `parseSubmissionReply(status, input)` enforces 200/ready or 202/nonterminal, active interest, no reconciliation flag. `statusReplySchema` strictly validates response shape.

A status has **two separate state dimensions**: `state` is the durable job lifecycle, `interestState` is `active | cancelled | expired`. Cancel does not pretend shared work stopped. `cancellationScope: 'interest-only'` iff the interest is cancelled, `sharedWorkCancelled: false` always. The artifact is present iff job ready **and** interest active. A cancelled interest may still report job rendering with reconciliation required; this is truthful. Ready/cancelled/expired jobs cannot carry uncertain execution in a valid reply.

## Identity, object boundary and immutable revision

`bindRequestSync(design, purpose, auth): RequestBinding` reuses the exact canonical inputs of `designIdentity` and the existing draft authorities with synchronous SHA-256. `bindRequest(design, purpose, auth): Promise<RequestBinding>` is its async-compatible service facade. It returns `{ purpose, identity, cacheKey, visibility, revision }`. `revision` equals the logical request digest. Image keys contain no principal or experiment; equal public designs can coalesce. Export keys include principal **and** experiment and a separate purpose namespace; no public/private cross-hit. Every response/lookup remains ownership checked even for public artifact bytes. A job's first authenticated caller is its immutable budget sponsor, not part of its public artifact identity.

The sole immutable key form is `p04/{public|private}/{cacheKeyHex}/{checksumHex}.svg`. `artifactId === checksum`, the checksum hashes actual encoded bytes, and the key binds checksum and visibility/request cache key. No caller URL, filesystem path or CDN hostname is accepted. `ArtifactDescriptor` contains binding, profile, dimensions, byte length, media type and the retained mock provenance. It always says `mock-diagnostic`, `approvedCurrentImage: false`, `strictExport: false`, `productionAllowed: false` and the visible label `MOCK DIAGNOSTIC — NOT A CURRENT DESIGN IMAGE`.

The object namespace is an immutable object/CDN **boundary**, not an already deployed CDN. Delivery uses the authenticated interest route and private/no-store response headers in this phase. Public image identity may later be an immutable CDN key, but no CDN or signed URL implementation is authorized here. Private exports are never made public simply because their SVG bytes equal another artifact's bytes.

Shared helpers:

- `sha256Bytes(bytes: Uint8Array): string`: actual SHA-256 identity.
- `canonicalJson(value: unknown): string`: stable key ordering for previously strict-parsed internal JSON. It is not a generic request validator.
- `immutableObjectKey(binding, checksum): string`: strict scoped content key.
- `diagnosticBytes(artifact: MockArtifact): Uint8Array`: decode only the strict diagnostic data URL.
- `verifyDiagnosticArtifact(input, design, maxBytes?): Promise<MockArtifact>`: reconstruct deterministic existing recipe, compare every metadata/byte field, digest, dimensions, profile and bound. No rendering, network or arbitrary SVG interpretation.
- `describeArtifact(artifact, design, binding): ArtifactDescriptor`: metadata projection only; NOT verification. The object store must verify first.
- `signVerifiedObject(claims, objectSecret): VerifiedObject` and `verifyObjectReceipt(input, objectSecret): VerifiedObjectClaims`: domain-separated HMAC over stage/execution/descriptor/verification time. The ledger authenticates the receipt and checks its execution/request binding; a caller-supplied boolean cannot make a job ready.

Secrets are injected, private, minimum 32 UTF-8 bytes, never request fields or logged. Worker, provider-receipt and object-verification keys should be distinct. Reopen must retain the same keys or fail closed; key replacement must not reset an existing ledger. Contracts provide signing primitives, not key management or auth grants.

## Durable ledger and lifecycle

Post-review amendment: `LedgerSnapshot.quarantinedExecutions` exposes authenticated provider contradictions separately from terminal job state and settled account balances. Each record retains the exact execution, prior receipt, contradictory receipt and `outstandingLiabilityUnknown: true`. A nonidentical same-or-newer sequence after final settlement, or an execution-bound breach, emits `provider-quarantined` and durably enables kill. Older/exact replays cannot settle a different attempt. Quarantine is not a new bounded reservation, an assertion of zero liability, or an automatic account correction; it cannot be cleared by replay, restart, retention or another final receipt. Such jobs are excluded from deletion candidates. External financial reconciliation requires a separately reviewed operator protocol.

All `Ledger` methods are synchronous SQLite transactions or bounded synchronous reads; never await with a transaction open. `LedgerOptions = { path, policy?: Partial<Policy>, now?: () => number, receiptSecret, objectSecret }`. Persist a normalized full policy plus key binding on first creation. Reopen must match it, not rewrite it. There is no reset, budget raise or kill-clear API. Keep spent totals, unique-miss counters, idempotency tombstones and kill evidence through retention/restart. Reopening unknown/corrupt/inaccessible state is 503, not a new ledger fallback.

`JobRecord` includes design/binding, sponsor, quote, fence, attempts, current execution, lease/deadline/availability times, reconciliation flag, spent/reserved amounts and nullable artifact/error. `Lease` includes a persisted execution identity, immutable design/binding/quote/policy, worker ID, lease expiry and original job deadline. Claim creates execution identity **before** any provider contact, so a watchdog can tombstone even a start that has not arrived yet.

### Events and allowed transitions

`requested → reserved → queued` may commit in a single admission transaction, but all three ordered events must be present. Main flow: `queued → leased → rendering → publishing → ready`. Recovery with proven settlement may `leased|rendering|publishing → queued`; no unknown retry. Known terminal outcomes may enter failed/cancelled/expired. `ready → expired` is the sole normal terminal-to-terminal retention transition. Repeating the same state is allowed only as an idempotent operation. `canTransition(from, to)` is a graph check, not execution authorization. `assertTransition(from, to, reconciliationRequired?)` blocks state changes while reconciliation is required, including fabricated cancelled/expired/ready outcomes.

Events exported in `eventKindSchema` are exactly: requested, reserved, queued, leased, heartbeat, rendering, publishing, ready, failed, cancelled, expired, interest-attached, interest-cancelled, receipt-recorded, reconciliation-required, reconciled, kill-enabled, stream-opened, stream-closed, object-deleted, delivery-recorded. State changes record from/to. Interest, meter, stream and delivery events may leave state unchanged. Global kill has nullable job/execution. No generic request text, secrets or URLs in detail.

Uncertain execution is a persistent `reconciliationRequired` flag on the retained job/execution (not a fabricated cancelled/stopped state). Missing provider outcome, a timed-out request, lost lease, process exit, stop request, and kill flag are **not final stop proof**. Fencing prevents stale publication, not external execution. Keep concurrency liability until proven settled. An over-bound provider outcome trips fail-closed handling; it must not manufacture an in-budget receipt or silently clamp the charge.

## Quote, caps and settlement

`policySchema` is strict, bounded and defaulted; `DEFAULT_POLICY` is frozen. `worstCaseQuote(policy): CostQuote` uses checked integer arithmetic. `checkedAdd(...values)` and `checkedMultiply(a, b)` reject negative, fractional, unsafe or overflowing values. Quote currency is `synthetic-micro`; `quoteSchema` checks exact component sum.

First-attempt startup/runtime/idle/shutdown/delayed-meter costs are each the bounded milliseconds × synthetic rate. `retries = (maxAttempts - 1) × (startup + runtime + idle + shutdown + delayedMeter)`. Delivery reserves maxOutputBytes × maxDeliveriesPerJob at the KiB rate. Storage reserves maxOutputBytes × maxAttempts (including orphan stages), for rounded-up hours covering retention + full job lifetime + shutdown + delayed-meter margin. Total includes all eight components. Delayed termination with no final meter retains liability beyond that estimate and blocks new work; it does not imply a real-provider guarantee. No real provider is implemented or approved.

The first miss sponsor's global/experiment/principal accounts reserve the **whole** job quote atomically. Later public coalesced interests do not sponsor a second execution; their bounded deliveries consume the first quote's explicitly reserved delivery allowance. This is a deliberate conservative sponsor model, not per-viewer billing. Per-principal interest limits still apply; users cannot change sponsor, create unbounded deliveries or evade a full pool. Private exports cannot cross principal/experiment sponsorship. If per-viewer billing is later desired it requires a separate accounting design, not an unreviewed interface change.

Budget invariant: for every account `spentMicro + reservedMicro <= limit`; update all three or none. Unique misses and spent are lifetime counters. Attempts, jobs/interests/principals/experiments, concurrency including unknown execution, output bytes, global storage allocation, cumulative delivered bytes, delivery count, runtime, lease/context lifetimes and streams all have persisted caps. Storage/delivery components remain held or are conservatively charged on completion; do not refund them when only the provider meter finalized. Storage byte allocation can be conservatively lifetime-bounded: deletion need not replenish a cap. Never release it merely because a DB row expired. Retention deletes artifacts/stages only with trustworthy ownership and references; it never resets financial/abuse ledgers.

## Private fake provider, signed context and receipts

`ExecutionIdentity = { provider: 'fake-local', executionId, jobId, fence, attempt }`. Every provider receipt binds every field. `sameExecution(a, b)` compares all fields. Context claims contain protocol, fixed private audience, execution, binding, strict design, issue/expiry timestamps (at most 60 s), max runtime, max output bytes, per-attempt maximum synthetic cost and `paidExecutionAllowed: false`. No commands, URLs, callbacks or user-selected worker settings.

- `workerClaimsForLease(lease, now): WorkerClaims` bounds expiry by lease, original job deadline and policy context TTL, and copies attempt caps.
- `signWorkerContext(claims, contextSecret): SignedWorkerContext` and `verifyWorkerContext(input, contextSecret, now): WorkerClaims` authenticate a domain-separated HMAC and reject expired/future/extended/unknown-field/paid-enabled contexts. Provider still validates design/binding consistency and its persisted tombstone before execution. Signature proves private authorization only, not that the ledger is still live; duplicate execute IDs remain idempotent.
- `signProviderReceipt(claims, receiptSecret): ProviderReceipt` and `verifyProviderReceipt(input, receiptSecret): ReceiptClaims` authenticate receipts independently of the worker key.
- Receipt claims include execution identity, monotonic sequence, observation time, cumulative synthetic cost and runtime, outcome (`running | stop-requested | stopped | completed | unknown`), `finalMeter`, and `startForbidden` durable tombstone evidence.
- `isSettledReceipt(claims)` requires stopped/completed + final meter + durable start tombstone. It does not itself verify HMAC, execution ownership, monotonicity or policy caps; the ledger must do all four. `{ confirmedStopped: true }` is not any accepted receipt.

`FakeProviderOptions = { path, contextSecret, receiptSecret, now? }`. Its durable journal/tombstones survive reopen and are local only. The provider cannot execute a different execution identity under an existing ID or restart a stopped/completed ID. A stop for an as-yet-unseen but ledger-authorized execution **must write a tombstone** before acknowledging; subsequent delayed start is refused. Successful completion also tombstones duplicate starts. A stop request during injected delayed termination returns stop-requested, not stopped. Tests may inject explicit fake delays and unknown outcomes; nothing invokes a renderer.

`WorkerOptions = { ledger, objects, provider, workerId, contextSecret, now?, providerCallTimeoutMs? }`.

- `Worker.runOnce(): Promise<number>` claims at most policy concurrency, returns number of claims actually attempted. Runs heartbeat while active, persists rendering before provider call, verifies receipt and diagnostic bytes, stages then begins publishing, publishes immutable file, then performs fenced ledger publish. Stale/kill/error paths cannot ready. A lost receipt is uncertain. A filesystem failure after provider settlement is a known failure only if provider final receipt remains verified; release neither untracked object storage nor arbitrary refunds.
- `Worker.shutdown(): Promise<void>` ceases this worker's admission, requests stops for its active identities if possible, and leaves unresolved liabilities durable. No parent browser/service/process control. It does not close shared ledger/provider owned by another component or certify stopped without receipts.

`WatchdogOptions = { ledger, provider, objects?, now?, providerCallTimeoutMs? }`.

Private provider-call deadlines default to 250 ms and accept only integer 1–5,000 ms overrides. Worker execution is separately bounded by the original job deadline. A shared per-provider call pool retains at most 64 unresolved operations, coalesces same-operation calls, and keeps timed-out slots until the underlying promise settles. Timeout never proves termination or refunds a reservation. Repeated ticks do not accumulate calls for a hung resource. Local stream closure occurs before inventory/stop awaits. These deadlines provide local asynchronous progress, not cancellation of a blocked event loop, remote provider or billed host; external adapters remain disabled.

- `Watchdog.tick(): Promise<WatchdogReport>` is timer-free, independently callable from a separate process opening the same durable store. Runs recovery, scans provider inventory for known expired/unknown and orphan hosts, requests stops, polls signed receipts, reconciles only proved outcomes, and closes owned fake stream resources. Store-unavailable path fails closed and may conservatively stop enumerated provider executions without pretending accounting reconciled.
- `Watchdog.kill(reason: string): Promise<WatchdogReport>` persists ledger kill first, then performs the same shutdown/reconciliation pass. It must stop/tombstone leased-but-not-started IDs, queued retries, active workers, orphan inventory and local fake streams. Repeated ticks handle delayed provider termination and delayed final meter without refunds.
- Report fields are killed, stopRequested, reconciled, retainedLiabilities, closedStreams, orphanExecutions, errors. `stopRequested` is not a count of stopped workers. Every error is bounded/non-secret. Orphans absent from the ledger are never silently admitted or treated as a ledger refund; stop them, retain provider inventory evidence and report them.

Sequence is stage → ledger.beginPublishing → immutable publish/readback → ledger.publish CAS. SQLite and filesystem cannot commit atomically. Crash before immutable publish leaves a staged orphan, never ready. Crash after immutable publish but before DB CAS leaves an unreferenced immutable orphan, never ready. Recovery first fences uncertain lease and retains liability; it must not infer job success from a matching filename. Explicit authorized retry/reconciliation may use the verified object, or retention can clean it under a fresh healthy reference snapshot. A stale worker can leave an orphan but cannot make a job ready. Reference snapshots are not a lock: automatic recovery reports final-object orphans instead of racing deletion with a publishing worker.

For local stage recovery, capture the age cutoff **before** the authoritative active/reference snapshot and delete only stages strictly older than that cutoff. This assumes local processes share a nondecreasing clock; same-timestamp/new stages are retained. Unknown partial stages remain pinned. Remote stores, clock rollback and distributed garbage collection require an authoritative deletion epoch/fence; no such qualification is claimed.

| Cancel        | `cancel(auth: AuthContext, interestId: string): Promise<StatusReply>`; appropriate authenticated ownership/scope, idempotent interest-only detach and honest remaining job state.                                                                                        |
| Deliver       | `artifact(auth: AuthContext, interestId: string): Promise<DeliveredArtifact>`; requires images:read and ownership/active interest, object verify/read, atomic recordDelivery before returning `{ object, bytes }`; kill/expiry/staleness after awaits must be rechecked. |

`ControlHttpOptions = { service, authenticate, bodyTimeoutMs?, maxConcurrentRequests? }`; `ControlMiddleware = (request, response, next) => void`. No listener creation is part of this interface. `interestPath(id)` and `artifactPath(id)` validate opaque IDs and return fixed local routes. Errors use `ControlError(status, code, boundedMessage, retryable?)`, `.wireError`, and `unavailable(message?)`. Do not expose raw database/filesystem/provider errors or auth tokens.

A real worker also heartbeats, handles every failure and preserves uncertain liabilities. `service.submitImage(auth, sameRequest)` returns 200 only after the ready object's bytes verify; a second public principal may attach a different owned interest but cannot read the first principal's status. `service.submitExport(auth, exportRequestFixture(sameDesign))` creates a private purpose-isolated job. `service.cancel(auth, interestId)` detaches that interest; `watchdog.kill('local operator stop')` is a separate private operator action that persists kill and issues execution-specific stops. Repeated watchdog ticks wait for final signed receipts; no boolean stop assertion or reset exists.

## Fixture and verification policy

`imageRequestFixture(design?: unknown, idempotencyKey?: string)` and `exportRequestFixture(...)` build strict requests from the existing `defaultDesign()` authority. Fixed test keys are idempotency data, not auth credentials. These helpers do not create authenticated contexts or scopes. Tests explicitly inject synthetic auth records/ephemeral signing keys and own disposable lane-local SQLite/directories; keys are not printed or saved as plaintext evidence. Existing `createDesignFixtures`/`createSceneDesignFixtures` may be reused; no new product/rights catalog or P03 receipts.

Owned contracts tests cover unknown/unsafe fields, named-v4/profile strictness, image/export separation, public/private identity, integer quotes/overflow, signed bounded context, execution-bound final receipts, lifecycle uncertainty, checksum/provenance/dimension/media rejection, immutable object proof, and response consistency. Other owners test persistence, concurrent transactions, object I/O/crash windows, kill/lease/stream/orphan/delayed-stop behavior and HTTP/auth. Interface definitions and pure-helper tests are **not evidence those integrations already work**.
